Production Deployment Checklist

Comprehensive operational checklist for deploying code and infrastructure changes into production environments. Use before initiating a deployment window, during traffic rollout, and during post-release verification to ensure zero unexpected outages, full stakeholder visibility, and strict compliance sign-off.

Phase 1: Pre-Flight Checks & Approvals

Verify all operational prerequisites, stakeholder sign-offs, and environmental health before touching production.

5 Checks
#pd-1

Change Approval Board (CAB) & Ticket Status

Verify that the Change Ticket is formally approved by CAB or authorized peer reviewer, and the scheduled deployment window is active.

CLI Command / Verification 
jira issue view PROD-DEPLOY-4421 --output json | jq .fields.status.name
#pd-2

Code Freeze & Release Branch Parity

Confirm the release branch has passed all CI unit, integration, and security scans with no merge conflicts or untested commits.

CLI Command / Verification 
git diff origin/main...origin/release-v2.14.0 --stat
#pd-3

Staging Environment Acceptance Sign-Off

Confirm QA, product owner, and automated E2E tests have passed 100% in the Staging/Pre-production environment.

CLI Command / Verification 
curl -s https://staging.internal.net/health | jq .status
#pd-4

On-Call & Stakeholder Notification

Post deployment announcement in #engineering-releases and #on-call Slack channels, listing primary operator, target services, and war room link.

CLI Command / Verification 
# Format: "[DEPLOY STARTING] Service: payments-api v2.14.0 | Owner: @oncall-eng"
#pd-5

Production Telemetry Baseline Verification

Check Datadog/Grafana dashboards to ensure production cluster is healthy, error rates are < 0.05%, and no active Sev1/Sev2 alerts are firing.

CLI Command / Verification 
kubectl get nodes && kubectl top nodes

Phase 2: Database, Migrations & Feature Flags

Safely handle database schema transformations, backwards compatibility, and feature toggle states.

4 Checks
#pd-6

Production Database Backup / Snapshot

Take or verify a fresh Point-in-Time (PITR) backup snapshot of production databases before applying any schema changes.

CLI Command / Verification 
aws rds create-db-snapshot --db-instance-identifier prod-postgres --db-snapshot-identifier pre-deploy-v2-14-0
#pd-7

Execute Backward-Compatible Migrations (Expand Phase)

Run database schema migration scripts ensuring non-blocking operations (e.g. ADD COLUMN nullable, CONCURRENT index creation).

CLI Command / Verification 
flyway migrate -url="jdbc:postgresql://prod-db:5432/app" -locations="filesystem:./migrations"
#pd-8

Feature Flags Configured in Dark / Default-Off State

Verify in LaunchDarkly / Unleash that all newly introduced features are disabled for general traffic and scoped to internal canary users only.

CLI Command / Verification 
curl -s -H "Authorization: $LD_API_KEY" https://app.launchdarkly.com/api/v2/flags/default/new-checkout-flow
#pd-9

Secrets & Environment Variables Synchronized

Confirm HashiCorp Vault / AWS Secrets Manager / K8s Secrets contain all new keys required by the upcoming version before rollout.

CLI Command / Verification 
vault kv get -mount=secret prod/payments-api
3

Phase 3: Rollout Execution & Traffic Shift

Execute progressive release strategy (Canary or Rolling) with automated canary health monitoring.

4 Checks
#pd-10

Deploy to Canary / Staged Replicas (5% Traffic)

Trigger deployment of new container image to canary workload or update Argo Rollouts / Kubernetes Deployment.

CLI Command / Verification 
kubectl set image deployment/payments-api payments-api=registry.company.com/payments-api:v2.14.0 --record
#pd-11

Canary Metric Soak & Error Rate Verification (10 min)

Observe HTTP 5xx error rate, p99 latency, and container CPU/memory usage on the canary pods compared to stable baseline.

CLI Command / Verification 
kubectl logs -l app=payments-api,version=v2.14.0 --tail=100 -f
#pd-12

Promote Traffic to 50% and 100%

Gradually increase traffic percentage to 50%, then promote to 100% full production traffic once canary metrics match SLA.

CLI Command / Verification 
kubectl argo rollouts promote payments-api || kubectl rollout status deployment/payments-api
#pd-13

Verify Pod Health & Zero CrashLoopBackOffs

Confirm all pods are in Ready state (1/1), zero restarts occurred during rolling replacement, and replica count matches target.

CLI Command / Verification 
kubectl get pods -l app=payments-api -o wide
4

Phase 4: Post-Deployment Smoke Tests & Sign-Off

Validate critical customer journeys, synthetic monitors, and formally close the change window.

4 Checks
#pd-14

Execute Automated Production Smoke Test Suite

Run end-to-end synthetic health checks targeting critical paths: authentication, payment processing, data retrieval, and logout.

CLI Command / Verification 
npm run test:smoke:production
#pd-15

Monitor APM & Error Tracking (Sentry / Datadog)

Actively monitor Sentry for any new unhandled exception signatures or sudden spikes in error budgets for 15 minutes post-deploy.

CLI Command / Verification 
# Monitor Sentry Issues dashboard filtered by release: v2.14.0
#pd-16

Clean Up Stale Resources & Invalidate CDN Caches

If frontend or static assets were updated, purge CDN edge caches (Cloudflare / CloudFront) to prevent cached script mismatches.

CLI Command / Verification 
aws cloudfront create-invalidation --distribution-id $DIST_ID --paths "/*"
#pd-17

Post Deployment Success Announcement & Close Ticket

Update #engineering-releases with final deploy status, link to changelog, and transition CAB change ticket to "Completed".

CLI Command / Verification 
jira issue transition PROD-DEPLOY-4421 --transition "Closed"
